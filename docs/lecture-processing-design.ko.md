# 긴 강의의 분할 전사와 전체 교정

> 이전 설계·실험 기록입니다. 현재 5분 파일 전사·전체 교정·용량 초과 시 이분할·교정 완료 후 공개 규칙은 [구현 상세](technical-guide.ko.md)에 정리했습니다.

5분 파일 한 개의 전사가 성공해도 73분 강의 전체가 완성된 것은 아니다. 녹음 중 만들어지는 구간을 빠짐없이 처리하고, 강의가 끝난 뒤 전체 맥락으로 교정하며, 원문·문장 ID·시간축을 보존해야 한다. 이 문서는 그 완료 조건과 실패 처리를 정의한다.

## 현재 구현과 남은 검증

녹음 중 최대 5분 단위 전송, 완료된 파일의 분할 처리, 구간별 저장·재개, 음향 정렬, 누락 의심 구간 재처리, 전체 맥락 교정, 제목·핵심 요약을 연결했다. 실제 실행 프롬프트는 [LectureReviewPrompts.swift](../Sources/SoriCore/LectureReviewPrompts.swift), 검증·요청 분할·캐시는 [LectureReview.swift](../Sources/SoriCore/LectureReview.swift)에 있다.

73분 강의는 실제 앱 경로에서 전체 교정과 핵심 요약까지 완료했다. 다만 일부 발언 오인식과 불확실한 재생 위치가 남는다. 처리가 끝났다는 사실과 정확한 전사문이라는 판단을 구분해야 한다. 5분은 관찰된 누락을 줄이기 위한 처리 단위이며 서버의 정확도 보장이 아니다. 설치된 이전 앱은 이 개발 빌드로 자동 교체하지 않는다.

## 녹음 파일을 기준으로 분할하고 완료를 판단한다

원본은 녹음 장치에서 로컬 파일로 계속 저장한다. 전사 작업의 지연·실패는 녹음 작업을 멈추지 않는다. 최대 5분이 쌓이면 끝의 10초 안에서 260 ms 이상의 쉼을 찾아 구간을 닫고, 완성된 구간 파일을 전송 큐에 넣는다. 같은 처리기를 가져온 파일에도 적용한다. 사용자에게는 하나의 녹음으로 보인다.

분할 시각은 네트워크 시계나 녹음 시작 이후의 벽시계가 아니라 저장된 오디오 샘플 좌표다. 일시 정지·절전·마이크 재연결이 있어도 실제 파일에 없는 시간이 타임라인에 추가되면 안 된다. 구간의 끝과 다음 구간의 시작이 맞는지 샘플 단위로 검증한다. 현재 파일 처리기는 쉼을 찾지 못하면 정확히 5분에서 자른다. 앞뒤 구간을 겹치지 않게 만들며 텍스트 중복 제거는 하지 않는다. 같은 말이 반복됐다는 이유로 삭제하지 않는다. 필요하다면 경계 오디오를 겹쳐 다시 인식하는 보완을 추가할 수 있지만, 아직 구현하지 않았고 경계 발화 보존은 실제 음성으로 검증해야 한다.

녹음 종료 시 마지막 5분 미만 구간까지 닫는다. 마지막 구간 번호와 전체 샘플 수를 기록한 manifest가 있어야 전체 완료를 판단할 수 있다. 모든 구간의 응답이 저장되기 전에는 합친 원문을 게시하지 않는다. 모든 응답을 받았다는 사실과 발언을 빠짐없이 인식했다는 사실은 별개다. 원문에는 `contentCoverageVerified=false`, `sentenceTimingVerified=false`를 기록하고, 정렬과 후속 검증을 거치기 전에는 제품 전체 완료로 간주하지 않는다. 먼저 성공한 구간이 있어도 순서는 구간 번호로 복원한다.

```text
녹음 → 원본 파일 저장
         └─ 닫힌 구간 → 전사 → 구간 원문 저장
녹음 종료 → 마지막 구간 닫기 → 저장된 구간 재사용 → 시간 정렬
         → 누락 의심 구간 재처리 → 전체 구간·시간축 검증
         → 전체 맥락 검토 → 수정 제안 검증 → 최종 교정본 저장
         → 교정본을 근거로 제목·핵심 요약 생성
```

녹음 중에는 `live-asr/`에 완성된 구간 WAV, 샘플 좌표, PCM 해시, 전사 응답을 저장한다. 종료 후 전체 파일의 각 PCM 구간과 해시를 다시 대조하고 언어·전략이 일치할 때만 이미 받은 응답을 재사용한다. 녹음 중 전송 오류는 마이크를 멈추지 않으며 60초 대기 후 다시 시도한다. 종료하면 마지막 구간을 닫고 미완료 구간을 처리한다.

완료된 파일 처리에서는 `asr-original.chunks/<입력 키>/`에 manifest와 구간 응답을 원자적으로 저장한다. 원본 SHA-256·언어·분할 전략·샘플 좌표가 같아야 재사용한다. 이전의 통째 전사 캐시를 새 5분 결과로 잘못 사용하지 않는다.

앱이 갑자기 종료돼 WAV 데이터 크기가 헤더에 반영되지 않은 경우, 열린 녹음 manifest와 PCM 범위·해시를 확인한 뒤 `audio-recovered.wav`를 별도로 만든다. 원본 `audio.wav`는 수정하지 않는다. 복구 파일과 원본의 해시를 영수증에 저장하며, 기존 복구 파일이 변경됐다면 덮어쓰지 않는다. 이는 파일 복구이며 실제 절전·마이크 분리 상황을 모두 검증했다는 뜻은 아니다.

## 시간 정렬의 불확실성을 숨기지 않는다

각 전사 구간은 해당 5분 오디오 안에서만 CTC 강제 정렬한다. 고정된 짧은 탐색 창 때문에 긴 구간이 실패하던 문제를 수정하되, 동적계획법 메모리 한도는 유지한다. 원본 PCM 해시에 묶인 음향 확률 캐시는 재시도 시 모델 추론을 반복하지 않도록 한다.

신뢰 기준을 통과한 문장만 자동 따라읽기에 사용한다. 낮은 점수의 문장은 `timingQuality=approximate`로 저장하고 화면에 ‘약’을 표시한다. 구간 전체를 정렬할 수 없으면 해당 구간 원문을 한 문단으로 보존하고 파일에서 확인한 구간 범위만 사용한다. 글자 수로 문장별 시간을 만들어내지 않는다. 다른 구간은 계속 처리한다.

전사문 사이에 대응되지 않은 음향 신호가 있으면 `reviewRanges`에 기록한다. 이것은 누락 가능성이지 발언 누락의 확정 판정이 아니다. 제한된 길이·횟수 안에서 해당 오디오를 다시 전사하고, 원래 범위 안에서 독립적으로 정렬된 결과만 합친다. 한국어가 지배적인 강의의 짧은 재처리 구간에는 한국어 힌트를 전달한다. 그래도 한글 없이 다른 언어로만 반환된 후보는 자동 삽입하지 않고 원응답과 확인 구간을 남긴다. 실제 영어 용어도 이 보수적 규칙에 걸릴 수 있으므로 삭제한 것으로 간주하지 않고 원음을 확인한다. 해결되지 않으면 앱에 ‘음성 확인 필요’로 남기고 해당 구간을 듣거나 확인 완료로 표시할 수 있다.

강제 정렬이 성공해도 단어가 맞다는 보장은 없다. 비슷한 발음의 오인식은 높은 정렬 점수를 받을 수 있다. 누락 검사도 모든 발언을 찾지 못하며, 원음 대조가 필요한 의미 오류를 교정 모델이 추측으로 메워서는 안 된다.

## 전체 맥락은 교정의 근거이며 정답지가 아니다

교정자는 음성을 듣지 않는다. 뒤쪽에서 명확히 반복되는 전문용어는 앞쪽 인식 오류를 고칠 근거가 될 수 있지만, 강의 주제를 추측했다는 이유만으로 용어를 고쳐서는 안 된다. 교수의 설명이 사실과 달라도 전사문에는 실제 주장을 남겨야 한다.

예를 들어 ‘브레트로즈’를 ‘브레턴우즈’로 수정하려면 다른 두 문장에 실제로 ‘브레턴우즈’가 등장해야 하며 동일 개념을 뜻해야 한다. 반면 ‘1997년, 아니 1998년’은 두 연도와 자기 정정까지 유지한다. ‘통제경제’와 ‘자본 통제’를 구분하는 강의를 용어 통일이라는 이유로 하나의 표현으로 바꾸지 않는다.

허용되는 변경은 띄어쓰기, 제한된 문장부호, 원문에서 근거를 확인할 수 있는 작은 인식 오류다. 언어·말투·고유명사·수치·부정·비교 방향·조건·예외·반복·학생 질문·자기 정정을 보존한다. 의미 복원, 번역, 질문에 대한 답변, 빠진 내용 채우기, 실제 발언의 사실 교정은 하지 않는다.

## 문장을 재생성하지 않고 작은 수정만 반환한다

모델에는 편집 가능한 ID를 명시한다. 응답은 `complete`와 `edits`뿐이며 변경하지 않은 문장은 응답에 다시 쓰지 않는다. 각 수정은 `segmentID`, 원문 `before`, 대체문 `after`, 변경 종류 `kind`, 근거 `evidence`를 갖는다. 타임스탬프 필드는 없다.

앱은 다음 조건을 검증한다.

- ID가 이번 검토 대상에 속하고 `before`가 그 문장에 정확히 한 번 존재한다.
- 서로 겹치거나 연쇄 적용을 요구하는 수정이 없고, 문장 전체의 누적 변경량도 제한 안에 있다.
- 숫자·라틴 변수·수식 기호·주요 부정과 비교 표현이 보존된다. 질문·인용·수식 기호의 변경을 문장부호 수정으로 우회할 수 없다.
- 인식 교정은 서로 다른 두 문장 이상의 실제 인용을 포함한다. 인용문은 원문에 존재하고 교정 후 표현을 포함해야 한다.
- 변경 후에도 원본 문장 수·ID·순서·`originalText`·시작/종료 시간이 그대로다. 모델이 출력한 새 문장 목록이나 시간은 사용하지 않는다.

검증은 구조와 일부 의미 변경을 제한한다. 인용이 실재한다는 사실만으로 두 표현이 같은 대상을 가리킨다고 증명되지는 않는다. 모든 한국어 수사·단위·논리 의미를 정규식으로 완전히 검증할 수도 없다. 따라서 프롬프트의 보수적 판단, 코드 검증, 실제 강의 평가가 모두 필요하다. JSON 스키마를 통과한 응답에도 의미 오류가 있을 수 있다. [OpenAI Structured Outputs의 오류 처리 설명](https://developers.openai.com/api/docs/guides/structured-outputs#handling-mistakes)

## 긴 강의에서도 마지막 부분을 버리지 않는다

일반 강의는 전체 전사문을 읽기 전용 문맥으로 주고, 최대 48문장씩 편집 대상을 지정한다. 각 요청이 같은 원본 전체를 보므로 앞뒤 내용과 자기 정정을 확인할 수 있다. 전사문은 어느 요청에서도 이전 요청의 교정본으로 대체되지 않는다.

전체 입력이 정해진 크기를 넘으면 모든 부분에서 원문 인용이 있는 용어 근거를 먼저 추출한다. 추출된 근거의 존재·ID를 검증한 뒤, 전체에서 모은 근거와 각 편집 대상의 주변 원문을 제공한다. 이 경로는 전체 원문을 한 번에 읽는 것과 동등하지 않다. 긴 강의에서 주제 간 관계를 놓칠 수 있으므로 근거가 부족하면 교정을 생략한다. 한도를 맞추려고 뒷부분을 잘라 버리지는 않는다.

검증에 실패하면 해당 문장 ID와 오류 종류를 알려 한 번만 재시도한다. 재시도 후에도 유효하지 않은 수정이 있으면 그 문장의 수정 전체를 버리고 원문을 보존한다. 다른 문장의 유효한 수정은 유지한다. 잘린 JSON, `complete=false`, 범위 밖 ID처럼 검토 완료를 신뢰할 수 없는 응답은 묶음 전체의 실패로 처리한다. 네트워크·인증 오류를 형식 오류처럼 반복 호출하지 않는다. 전체 검토가 끝나지 못하면 전사 원문으로 요약을 계속하고 교정 미완료를 알린다.

## 원문과 교정본을 별도로 보존한다

ASR 원문과 정렬 결과는 그대로 두고 `final-review.json`에 수정 제안과 원문 해시, 프롬프트 버전, 모델, 추론 수준을 저장한다. 검토가 끝난 묶음은 `final-review.json.parts/`에 따로 저장한다. 연결이 끊겨도 다음 실행에서 같은 원문·모델·프롬프트에 해당하는 검증된 묶음을 다시 사용한다. 모든 묶음의 검토가 끝나야 최종 파일을 원자적으로 저장하고 교정 성공으로 반환한다. 마지막 요청이 실패하면 앞부분만 교정된 버전은 게시하지 않는다. 최종 파일에는 적용한 수정과 원문을 유지한 문장의 검증 오류를 함께 남긴다.

원문·ID·시간·사용자 편집 중 하나라도 달라지면 해시가 바뀌고 이전 교정 캐시를 재사용하지 않는다. 모델이나 프롬프트 버전이 달라도 다시 검토한다. 유효한 캐시라도 다시 원문에 대조해 검증한다. 취소는 실패 복구로 삼키지 않고 호출자까지 전달한다. 저장 실패는 성공으로 표시하지 않는다.

## 예외별 처리 기준

| 상황 | 처리 기준 | 현재 상태 |
|---|---|---|
| 숫자·연도 모순, 교수의 사실 오류 | 원문 유지. 상식이나 후반 주장으로 앞부분을 바꾸지 않음 | 프롬프트·일부 코드 검증 |
| 고유명사·동음이의어·전문용어 불확실 | 명확한 원문 근거가 없으면 변경하지 않음 | 프롬프트·인용 검증 |
| 한국어·영어 혼용, 변수·수식 | 언어와 표기를 보존, 번역·변수 변경 금지 | 프롬프트·일부 코드 검증 |
| 자기 정정·더듬음·강조 반복 | 삭제하거나 문장을 매끈하게 재작성하지 않음 | 프롬프트·수정 범위 검증 |
| 잘린 문장·안 들린 말·침묵 | 내용 추측 금지. 교정으로 ASR 누락을 감추지 않음 | 프롬프트 |
| 전사문 속 명령·역할 위조·JSON | 데이터로 취급. 도구 비활성화, 제한된 수정 응답만 허용 | 프롬프트·실행 격리·스키마 |
| 미등록 ID·가짜 인용·중복/겹친 수정 | 한 번 재시도. 문장 단위 오류는 해당 원문 보존, 범위·구조 오류는 전체 교정 보류 | 구현·테스트 |
| 입력·출력 한도·후반 요청 실패 | 입력을 빠짐없이 검토, 불완전한 교정본 게시 금지 | 구현·테스트 |
| 취소·저장 실패·오래된 캐시 | 취소 전달, 저장 전 성공 금지, 해시·버전 확인 | 구현·테스트 |

| 앱 종료·절전·마이크 해제 | 닫힌 구간과 마지막 파일 복구, 샘플 기준 시간 복원 | 중단된 WAV 복사본 복구 테스트 완료, 실제 절전·장치 해제 검증은 별도 |
| 순서가 바뀐 응답·구간 재전송 | 구간 키로 저장, 중복 작업의 결과 하나만 채택 | 순차 전송·샘플 해시·완료 응답 재사용 구현 |
| 구간 경계 누락·겹침 | 오디오 범위로 판정, 텍스트 유사성만으로 삭제 금지 | 연속 샘플 분할·PCM 보존 테스트 완료, 발언 누락 검증 별도 |

모든 예외를 사전에 나열해 없앨 수는 없다. 미분류 오류도 원본 녹음·ASR 원문·기존 사용자 편집을 잃지 않고, 완료하지 않은 작업을 완료로 표시하지 않는 것이 공통 기준이다.

## 검증 완료의 범위

단위 테스트는 보호할 표현, 실제 인용, 수정 범위, 모든 부분의 검토 대상 포함, 캐시 무효화, 취소·저장 실패, 문장별 거부와 교정 재개, 성장 중인 WAV의 분할·복구를 확인한다. 실제 Sol/ASR을 사용한 성장 WAV 실험에서는 녹음 중 응답 저장과 종료 후 재사용을 확인했다. 이 실험은 마이크 장치를 사용하지 않는다. 실제 Sol 호출은 따로 기록하며 이 결과를 강의 전반의 정확도 보장으로 해석하지 않는다.

제품 전체의 완료 조건은 실제 73분 녹음의 모든 구간 처리, 분할 경계의 누락·중복 확인, 처음·중간·끝의 재생 위치 검증, 원문/교정본 비교, 네트워크 중단 후 재개까지다. 이 조건을 충족하기 전에는 긴 강의 지원이 완성됐다고 보고하지 않는다.
