# 녹음 종료 후 진행 상태

Apple Speech 전환 후 음성 인식은 빠르게 끝나지만 AI 교정과 핵심 요약은 별도로 기다려야 한다. 화면에서는 **음성 인식 → 전사문 교정 → 핵심 요약**의 세 단계를 보여주고, 진행 바를 현재 단계 아래에 배치한다. 전체 작업의 완료율로 오해할 수 있는 단일 백분율은 사용하지 않는다. 결과 저장은 마지막 단계의 마무리로 표시한다.

| 상태 | 표시 기준 |
|---|---|
| 음성 인식 | 체크포인트에 반영된 음성 길이 / 전체 길이. 이미 처리한 구간도 포함한다. |
| 최초 언어 모델 준비 | 다운로드 비율을 별도로 표시한다. 비율을 모르면 로딩 표시만 사용한다. |
| 전사문 교정 | 기존 보수적 시간 추정식을 사용하고 `예상 n% · 시간 기준 추정`으로 명시한다. 연결 확인이 끝나고 교정 요청을 시작한 시점부터 계산한다. |
| 교정 지연 | 예상 시간을 넘으면 응답 대기 안내를 추가한다. 시간만으로 완료 처리하지 않는다. |
| 핵심 요약 | 단일 요청은 로딩 표시와 현재 작업 설명을 제공한다. 분할 분석에서는 최종 통합까지 전체 작업 수에 포함한다. |
| 대기열 | 앞선 녹음 수와 자동 시작 안내. 다른 작업의 완료 상태나 경과 시간을 가져오지 않는다. |

교정 결과 전체를 검증·저장한 뒤에만 전사문을 공개한다. 이후 요약이 진행되는 동안은 작은 배너로 전환해 전사문을 먼저 읽을 수 있음을 안내한다. 요약만 다시 만드는 경우에는 해당 작업만 표시한다. 완료 후에는 기존의 완료 알림과 결과 화면으로 이어진다.

`나중에 이어하기`는 현재 요청을 중지하되 녹음과 완료한 체크포인트를 보관한다. 진행 중이던 요청 자체를 일시 정지하는 기능은 아니므로 재개 시 미완료 요청은 다시 실행될 수 있다. 중지 처리 중에는 버튼을 비활성화하고 저장 안내를 보여준다.

## 구현과 검증

- `ProcessingProgress.indicator`가 실측·추정·비율 미확정·실패를 구분한다. 추정치는 90%를 넘지 않고, 검증된 완료 응답이 우선한다.
- 같은 교정 단계의 재시도는 추정 시작 시각을 초기화하지 않는다. 단계가 바뀌거나 다음 녹음을 시작하면 초기화한다.
- 최소 창에서는 여백과 보조 문구를 줄인다. 더 작은 본문 영역에서는 스크롤할 수 있다. 모션 줄이기 설정에서는 수치 변경 애니메이션을 생략한다.
- 단위·파이프라인 테스트는 추정 지연, 잘못된 수치, 실패 시 가짜 완료 방지, 작업별 상태 분리, 긴 요약의 통합 완료 시점을 확인한다.
- `scripts/verify-ui.py`의 `processing`, `polishing`, `polishing-minimum`, `polishing-overrun`, `speech-download`, `summary`, `summary-only`, `queued`, `interrupted` 시나리오로 화면을 재현한다. 임시 샘플 라이브러리만 사용하며 음성 인식·AI 요청·실제 창 활성화는 하지 않는다.

시간 추정은 완료 시각을 보장하는 ETA가 아니다. 실제 서버 속도를 새로 측정하거나 전사 정확도를 변경하는 작업도 아니다.
