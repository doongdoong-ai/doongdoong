# 둥둥이 구현·운영 상세

둥둥이는 **전사 → 보정 → 강조 내용 분석**으로 책임을 나눕니다. 전사 엔진은 `doongdoong-ai/transcription-core`, 텍스트 AI 연결은 `doongdoong-ai/codex-core`에 분리했습니다. 강의용 프롬프트·분할·재시도·원문 및 근거 검증은 앱에 남아 공급자 교체와 독립적으로 유지됩니다.

## 전사 코어와 앱의 경계

| 구성 | 입력 → 출력 | 소유 코드 |
|---|---|---|
| 전사 | PCM WAV → 원문·시작/종료 시각 | 독립 패키지 `DoongdoongTranscription` |
| 공급자 공통 계약 | 지침·입력 JSON·스키마 → 응답 JSON | `DoongdoongAI/TextGenerationProvider` |
| Codex 연결 | ChatGPT 로그인·모델 조회·CLI 실행 | `DoongdoongCodex/CodexTextProvider` |
| 보정 | 원문·문장 ID → 검증된 교정문 | `SoriCore/LectureReview.swift`, 앱 파이프라인 |
| 강조 분석 | 전사문 → 제목·근거가 있는 요약 카드 | 앱 `TranscriptionPipeline` |
| 녹음·라이브러리·재생 | 사용자 조작 → 파일·UI | `SoriApp` |

앱의 `SoriSpeech/LocalTranscription.swift`는 코어 출력을 기존 `TranscriptSegment`로 바꾸는 어댑터입니다. 코어는 SoriCore, SwiftUI, Codex, 로그인 정보에 의존하지 않습니다. 원문과 타임스탬프는 코어가 결정하고, 보정은 문장 ID·원문·시간을 바꿀 수 없습니다.

## Apple Speech로 증분 처리

AVAudioRecorder가 16 kHz·mono·PCM16 WAV를 저장합니다. 녹음 중 전사는 **저장된 음성의 25분 경계마다** 시작합니다. 앱은 2초마다 저장된 PCM 길이만 확인하며, 다음 경계 전에는 전사 엔진을 준비하거나 호출하지 않습니다. 녹음 일시 정지·잠자기로 파일이 늘지 않은 시간은 주기에 포함하지 않습니다. 작업이 지연되면 여러 타이머 작업을 쌓지 않고 현재 저장된 분량을 한 번에 따라잡습니다.

25분은 실행 주기이며 디코딩 요청의 길이가 아닙니다. 실행할 때는 최대 60초 구간의 끝부분 5초에서 260 ms 이상의 쉼을 우선 경계로 사용합니다. 구간별 체크포인트로 실패·중단 시 재작업을 제한하고 메모리 사용을 제한합니다. `SpeechAnalyzer` 분석 세션은 구간마다 만들지만, 모델을 매번 다시 로딩한다는 뜻은 아닙니다. 짧은 구간끼리는 아래의 모델 유지 정책으로 재사용할 수 있습니다. 이미 처리한 음성을 겹쳐 반복 디코딩하지 않습니다.

`AppleSpeechEngine` 하나를 녹음과 파일 가져오기 세션이 공유합니다. `SpeechAnalyzer` + `SpeechTranscriber`가 기기에서 파일을 분석하고, `AssetInventory`가 언어 지원 확인과 필요한 모델 설치를 맡습니다. 앱 설정에는 준비 상태와 다운로드 진행을 표시합니다. 마이크 권한은 녹음에 필요하며, 파일 전사는 마이크를 열지 않습니다. 명시적 언어를 사용하고 이전 `auto` 설정은 한국어로 이관합니다.

FIFO gate가 준비·추론을 직렬화하고 대기 중인 작업의 취소도 처리합니다. `.lingering` 정책으로 짧은 구간 사이의 모델 재사용을 시스템에 맡깁니다. 자식 프로세스·localhost HTTP·Whisper 런타임·GGML 모델·Silero VAD가 없습니다. `unload()`는 이 엔진이 소유한 언어 예약만 해제하며 시스템 자산을 삭제하지 않습니다.

Apple이 반환한 시간 속성 텍스트 run을 문장부호 또는 100자·12초 기준으로 묶습니다. 텍스트 일부의 시간 정보가 빠지거나 유효하지 않으면 결과 구간 시각을 사용해 원문을 보존합니다. 실제 음성과 완벽히 일치한다는 보장은 아닙니다. 새 `timingQuality`는 `apple-speech`이며 과거 `whisper`·`aligned` 기록도 그대로 재생합니다.

디지털 무음은 인식기에 보내지 않지만 작은 발화는 진폭 기준으로 제거하지 않습니다. 정상 종료에서는 대기 중인 확인 작업을 즉시 취소하고, 이미 진행 중인 전사 묶음은 마무리합니다. 최종 파이프라인은 25분을 기다리지 않고 남은 모든 구간을 전사합니다. 25분보다 짧은 녹음도 동일하며, 파일 가져오기는 이 주기를 적용하지 않고 즉시 처리합니다. 취소·잠자기에는 `cancelAndFinishNow()`로 분석을 중단합니다. 구간 분석에 180초 제한을 둡니다.

## 실패·재개·분석

구간 완료 전에는 커서를 전진시키지 않습니다. PCM SHA-256·언어·분할 설정·엔진과 OS 버전을 확인한 결과만 재사용합니다. Apple 모델의 독립 revision은 확보하지 못하므로 같은 OS에서 모델만 갱신되는 경우까지 식별하지는 못합니다. 기존 Whisper 체크포인트는 새 전사에 섞지 않습니다. 같은 작업 폴더의 중복 처리는 파일 잠금으로 막습니다.

전사 오류는 녹음을 중단하지 않고 30초 뒤 재시도합니다. 묶음이 성공하기 전에는 다음 25분 경계로 넘어가지 않으며, 이미 완료한 내부 구간은 재사용합니다. 잠자기 후 계속 녹음할 때는 새 세션이 기존 체크포인트를 읽습니다. 저장된 음성이 25분 이상이면 미완료 구간을 먼저 보완하고 다음 경계부터 주기를 따릅니다. 미완성 WAV 헤더는 별도 audio-local-recovered.wav로 복구하며 원본은 덮어쓰지 않습니다. 이전 앱의 live-asr 녹음 복구도 유지합니다.

전사 원문은 내부 체크포인트에 먼저 저장하고 **전체 교정이 검증된 뒤에만 `recording.json.segments`로 공개**합니다. AI 연결이 없거나 교정이 실패하면 전사문을 공개하지 않고 재개 상태로 남깁니다. 교정이 완료되면 요약 중에도 읽기·복사·재생이 가능합니다. 요약 실패는 이미 검증된 전사문을 숨기지 않습니다. 재처리 중에는 기존 공개본과 사용자 편집을 유지합니다.

교정은 강의 전체를 한 번에 요청합니다. 입력·출력 용량 초과에만 문장 경계를 유지하며 JSON 바이트 크기가 비슷한 두 부분으로 나눠 재귀적으로 재시도합니다. 각 부분에는 앞뒤 세 문장의 읽기 전용 맥락도 포함합니다. **분할된 요청은 전체 원문을 보지 못한다는 한계**가 있으므로 이를 전체 문맥 교정과 동일한 품질로 간주하지 않습니다. 용어 요약으로 전체 원문을 대체하던 경로는 제거했습니다. 인증·사용량·네트워크·제한 시간 오류는 분할하지 않습니다.

모델은 전체 문맥을 검토한 뒤 `{ids, before, after}` 수정 계획만 반환합니다. 같은 수정은 여러 문장 ID를 묶되, 지정되지 않은 곳을 일괄 치환하지 않습니다. 문장마다 인용문을 생성하던 계약은 제거했습니다. 원문에 올바른 형태가 두 번 이상 있어야 한다는 제한도 없애 문맥상 명백한 희귀 용어를 교정할 수 있게 했습니다. 편집 종류와 실제 원문 용례는 앱이 계산해 기록합니다. 원문 용례가 없다는 사실을 숨기거나 근거를 만들어내지 않습니다.

로컬 검증은 정확한 문자열 위치·ID·겹침·수정량·숫자와 단위·부정·수식을 확인하고, 명사 치환으로 새로 생긴 명백한 조사 결합 오류도 거릅니다. 원문 용례가 없는 서술어를 바꿀 때는 공통 어미나 주변 단어 때문에 변경량이 작아 보이지 않도록 해당 어절의 자모 거리도 확인합니다. 이는 제한된 휴리스틱이며, 모든 의미 변경이나 잘못 추정한 고유명사를 판별하지는 못합니다. 전체 문맥에 기반한 모델 판단의 품질은 실제 교정 결과로 별도 평가합니다.

입력은 요청별 500,000바이트, 출력은 1,000,000바이트의 앱 제한을 두며 모델의 토큰 한도와 구분합니다. `codex-core`는 CLI JSONL의 종료 오류 이벤트를 판별하여 공급자 공통 `TextGenerationError.capacityExceeded`를 반환합니다. 모델 답변·일반 stderr를 오류 코드로 해석하지 않습니다. JSONL 이벤트와 `--output-last-message` 병용은 [공식 비대화형 모드 문서](https://learn.chatgpt.com/docs/non-interactive-mode)에 근거합니다. 알 수 없는 오류는 분할하지 않고 재시도로 안내합니다.

완료한 교정 부분과 분할 결정은 원문 해시·프롬프트 버전·공급자·모델·추론 강도에 묶어 저장합니다. 모든 부분이 완료돼야 최종 교정본을 원자적으로 커밋합니다. 정상 JSON에서 일부 제안이 검증에 실패하면 그 제안만 제외하고 같은 문장의 독립적인 정상 수정도 보존합니다. 서로 겹치는 제안은 모두 제외하고, 남은 수정의 문장별 누적 변경량을 다시 검사합니다. 이 때문에 전체를 다시 요청하지 않습니다. JSON 계약 오류는 한 번 재시도하며, 불완전 응답은 한 번 재검토한 뒤 범위를 줄입니다. 단일 문장까지 줄여도 실패하거나 깊이·요청 수 제한에 닿으면 중단합니다. 강조 분석은 실제 발화의 강조 근거와 원문 인용을 검증합니다.

## 잠자기와 갑작스러운 종료

녹음기를 열기 전에 복구 표식을 남기므로 첫 전사 요청 전에 앱이 종료돼도 복구할 수 있습니다. 저장된 PCM의 완전한 샘플만 별도 WAV로 복구하고, 원본은 보존합니다. WAV 뒤의 메타데이터는 음성으로 읽지 않습니다. 별도 엔진 프로세스를 실행하지 않으므로 강제 종료 뒤 남는 앱 소유 인식 서버가 없습니다.

앱은 NSWorkspace 전용 알림 센터의 `willSleepNotification`에서 녹음·재생을 동기적으로 일시 정지하고 메모와 작업 의도를 저장합니다. 실행 중 추론 취소·엔진 해제는 비동기로 처리합니다. Apple 문서는 [잠자기 전 알림](https://developer.apple.com/documentation/appkit/nsworkspace/willsleepnotification)과 [깨우기 알림](https://developer.apple.com/documentation/appkit/nsworkspace/didwakenotification)을 이 알림 센터에서 받도록 명시합니다.

깨우면 잠자기 때문에 중단한 활성 작업과 대기열을 같은 순서로 재개합니다. 마이크는 자동으로 켜지지 않으며 사용자가 **계속 녹음**을 누릅니다. 반복된 잠자기 알림과 오래된 깨우기 작업은 세대 식별자로 구분합니다. 사용자가 취소한 작업은 자동 재개하지 않습니다. 강제 종료 후 재실행에서는 파일만 복구하고 **이어서 정리**를 기다립니다. 요약만 재시도하던 작업은 그 의도를 보존하여 전사나 사용자 편집을 덮어쓰지 않습니다.

잠든 동안의 소리와 아직 디스크에 기록되지 않은 음성은 복원할 수 없습니다. 재실행 뒤에는 저장된 음성을 정리할 수 있으며 이전 녹음기에 이어 마이크를 자동으로 붙이지 않습니다. 실행 중이던 외부 요청은 서버에서 이미 처리됐을 수 있고, 커밋되지 않은 요청은 재개 시 반복될 수 있습니다.

## 공급자 설정과 실행

앱 실행 및 경로 변경 시 벤더 코어의 `CodexConnection.verifyConnection()`을 호출합니다. 코어는 ChatGPT 계정과 모델 목록을 확인하고, 선택한 모델·추론 강도로 짧은 JSON 테스트 요청을 보냅니다. 응답까지 검증해야 연결된 것으로 표시합니다. 자동 선택은 Sol, Luna 순이며 직접 선택한 모델은 실패하더라도 바꾸지 않습니다. 확인은 전체 90초로 제한하고 자동 재시도하지 않습니다. 테스트 요청에도 계정 사용량이 적용되며 녹음·전사문은 포함하지 않습니다.

공통 `ProviderConnectionChecking` 계약과 `ProviderConnectionIssue`는 `DoongdoongAI`에 있습니다. 설치·인증·설정·네트워크·서비스·사용 한도·시간 초과·응답 오류의 판정은 벤더 코어가 맡습니다. 알 수 없는 실패는 `unknown`, 사용자 취소는 `CancellationError`로 구분합니다. 사용 한도 초과 후 관련 재설정 시간을 확인할 수 있으면 함께 반환합니다. 브라우저 로그인은 `account/login/start` → 완료 알림으로 처리하며, 성공 후 실제 연결을 다시 검사합니다. 인증 정보는 CLI가 관리합니다. [공식 계정 API](https://learn.chatgpt.com/docs/app-server#auth-endpoints)

둥둥이는 최초 설정 완료 여부를 벤더별로 저장하되 현재 연결 상태와 구분합니다. 최초 확인에 실패하면 원인에 맞는 로그인·설정·재시도를 안내하고, 연결에 성공하면 요청하던 녹음·정리를 이어갑니다. 새 녹음은 전사·다듬기·핵심 요약까지 자동으로 진행하며, 처리 중 중단된 작업은 저장된 진행 상태를 바탕으로 재시도합니다. 모델이나 추론 강도를 바꾸면 이전 확인 결과를 무효화하며, 늦은 응답이 새 상태를 덮어쓰지 못하도록 요청 세대를 구분합니다. 진단 복사에는 공급자와 분류된 단계·사유만 포함합니다.

설정에서 AI 정리 사용 여부, 모델, 추론 강도, 요청별 제한 시간(기본 5분), 실행 파일 경로를 관리합니다. 추론 강도는 카탈로그가 보고한 값만 선택할 수 있습니다. `AppSettings.makeTextProvider()`가 현재 설정으로 공급자를 만들고, `AppStore`가 작업 시작 시 음성 인식 설정과 공급자를 고정합니다. Codex 공급자의 설정은 불변이므로 실행 중 설정 변경은 다음 작업부터 반영됩니다.

`TranscriptionPipeline`은 `SpeechConfiguration`과 `TextGenerationProvider`를 전달받습니다. 공급자 생성·선택이나 Codex 경로·모델을 알지 않습니다. 공급자가 없으면 음성 인식 결과를 내부 체크포인트에 보관하고 교정 전 공개를 막습니다. 요약만 처리하는 경로는 공급자를 필수로 받습니다. `LectureReview.review`의 공급자 식별자도 필수 인자이며, 실제 공급자·모델·추론 강도를 기준으로 교정 캐시를 구분합니다.

`CodexTextProvider`는 각 요청 전에 ChatGPT 로그인 상태를 확인하고 API 키 로그인을 거부합니다. 사용자 설정과 규칙을 제외하고 모델·공급자·추론 강도를 명시합니다. 요청별 비공개 임시 작업 폴더에서 CLI를 실행하고 종료 시 정리합니다. 앱은 응답의 JSON 문법뿐 아니라 문장 ID·수정 범위·숫자·부정 표현·근거 인용을 검증합니다. 관련 설정은 [공식 설정 문서](https://developers.openai.com/codex/config-reference/)를 기준으로 하며 CLI 0.160.0에서 명령 옵션을 확인했습니다.

향후 다른 공급자는 `TextGenerationProvider` 구현과 해당 벤더의 설정·생성 경로를 추가합니다. 예상 시간도 `estimatedDuration(for:)`의 필수 구현으로 제공하며, 벤더 사이에 공유하는 기본 계산식은 없습니다. 주입한 공급자는 Codex 설치·모델 조회 없이 요약과 중단 작업 재개에 사용할 수 있으며, AI 정리 사용 여부는 동일하게 적용됩니다. 공급자 구현은 전사 엔진이나 SwiftUI를 참조하지 않습니다. 로컬 경량 LLM PoC는 채택하지 않았으며, 실험 결과·프롬프트·실행 식별자는 비공개 `.local`에 보관합니다.

## 실제 완료량을 표시하는 진행 상태

진행 화면은 녹음 마무리, 음성 인식, 전체 맥락 확인, 문장 교정, 요약, 긴 강의의 요약 통합, 저장을 구분합니다. 사용자에게는 **음성 인식·전사문 교정·핵심 요약** 세 단계로 묶어 보여 줍니다. 저장은 마지막 단계의 마무리로 표시하며, 진행 바는 현재 단계 아래에 배치합니다.

전사는 체크포인트 검증 후 실제 완료한 음성 길이를 표시합니다. 교정과 단일 요청 요약은 벤더 코어가 반환한 시간을 **예상 진행률**로 표시합니다. 앱은 작업 종류와 글자 수를 전달하며, 시간 계산식이나 벤더별 분기는 갖지 않습니다. 현재 Codex 공식은 보수적인 초기 추정이며 실측 학습값은 아닙니다.

앱의 `EstimatedProgressCurve`는 표시만 담당합니다. 단조 시계의 경과 시간 `t`, 코어가 준 예상 시간 `d`에 대해 `0.9 × (1 − exp(−1.8t/d))`로 올립니다. 연결 확인 이후 교정 요청 시점부터 계산하며, 예상 시간에 약 75%이고 오래 기다려도 90%를 넘지 않습니다. 분할·재시도는 시계를 초기화하지 않으며, 실제 전체 검증이 끝나야 100%로 바뀝니다. 여러 구간을 요약할 때는 최종 통합까지 포함한 실제 작업 수를 표시합니다.

코어 CI는 모델·추론 강도·작업 종류와 글자 수 경계값에 대해 유한한 양수 예상 시간을 요구합니다. 앱 CI는 서로 다른 가짜 벤더의 예상값이 각각 교정·요약 표시로 전달되고, 생성 완료 전에는 100%를 표시하지 않는지 검사합니다.

교정이 끝난 전사문이 있으면 위쪽의 작은 진행 패널에서 상태를 확인하며 읽기·재생을 계속할 수 있습니다. 대기 중인 녹음은 앞선 작업 수를 보여 주고, 실패한 단계는 확인 필요로 표시합니다. 요약만 재시도할 때는 핵심 요약만 표시합니다. 표시 규칙과 재현 방법은 [진행 상태 문서](processing-progress.ko.md)에 정리했습니다.

Apple 전사는 언어 모델 준비 이후 계정·인터넷·API 비용이 필요 없습니다. Codex는 텍스트 교정·제목·핵심 요약에만 사용하며 계정 한도가 적용됩니다. 이전 내부 받아쓰기·MMS 구현은 과거 비교·복구용으로 남아 있지만 현재 제품 전사 경로에서는 호출하지 않습니다.

## 준비와 빌드

macOS 26+, Swift 6.2·macOS 26 SDK가 필요합니다. Apple Silicon M1에서 검증했습니다. Homebrew의 FFmpeg는 가져온 파일을 PCM으로 변환할 때 사용합니다.

```sh
brew install ffmpeg
./scripts/setup-engine.sh
swift test
./scripts/build-app.sh
```

설치 스크립트는 OS와 Swift 패키지를 확인하며 별도 음성 모델을 설치하지 않습니다. 앱의 언어 모델 준비 또는 첫 전사에서 macOS가 자산을 설치합니다. 과거 모델 파일은 자동 삭제하지 않으며 현재 앱에서 읽지 않습니다.

독립 CLI는 코어의 `doongdoong-transcribe`, 앱의 CLI는 `DoongdoongTranscribe`입니다. 인자는 `AUDIO OUTPUT_DIRECTORY [LANGUAGE]`이며 교정이나 로그인은 실행하지 않습니다.

--library는 격리된 라이브러리, --demo --snapshot은 창 없는 렌더링입니다. --integration-report는 창·마이크 없이 전사부터 Codex 분석까지 검사하므로 로그인과 계정 한도가 필요합니다.

## 데이터 보관

기본 위치는 ~/Music/둥둥이이며 기존 붕붕이·Sori 라이브러리도 읽습니다. 처리 중에는 이동·삭제를 제한하고 메타데이터를 원자적으로 저장합니다.

```text
녹음 폴더/
├── audio.wav                    # 원본 PCM
├── recording.json               # 공개된 교정문·메모·파형·요약·중단된 작업 의도
├── local-transcription/         # 구간별 원문·시각·PCM 해시·재개 기록
├── local-asr-original.json       # 합친 원문과 타임스탬프
├── audio-local-recovered.wav    # 중단된 녹음 복구 시에만 생성
├── final-review.json            # 검증된 교정 결과
├── final-review.json.parts/     # 내부 분할 결정과 완료한 교정 부분
├── processing-times.json        # 단계별 시간
└── transcript-history/          # 재처리 전 기존 기록
```

[중단·교정 공개 검증](validation-interruption-recovery.ko.md) · [Apple 전사 전환 검증](validation-apple-transcription.ko.md) · [이전 파일 전사 검증](validation-codex-file-transcription.ko.md) · [외부 구성요소](third-party-notices.md)

외부 배포용 서명·공증, 화자 분리, 시스템 오디오 녹음, 단어 단위 정렬은 현재 지원하지 않습니다.

## 녹음과 읽기

- 녹음 일시 정지·재개, 입력 레벨, 완료 후 AI 정리 대기열.
- WAV·M4A·MP3 및 동영상 음성 가져오기, 여러 파일 선택·드래그 앤드 드롭.
- 문장 클릭, 반복 재생, 파형 탐색, 10초 이동, 0.5–2배속, 집중 모드.
- 폴더별 녹음 탐색, 이동·이름 변경, 폴더 전체의 제목·텍스트·메모 검색.
- 필기 자동 저장, 문장 편집·원문 보기, 글자 크기 조절.
- TXT·SRT·JSON 내보내기, macOS 휴지통으로 삭제.

`도움말 → 샘플 녹음으로 둘러보기`는 미리 준비한 합성 음성과 텍스트를 사용합니다. 샘플 열기는 새 AI 작업을 실행하지 않습니다. 실제 엔진 검증은 별도 통합 검사로 수행합니다.
