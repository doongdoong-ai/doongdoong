# 중단 복구·전체 교정·공개 시점 검증

2026-10-21, M1 MacBook Air·macOS 26.3에서 합성 PCM과 가짜 공급자를 사용했다. 실제 사용자 라이브러리, 마이크, Mac 잠자기를 테스트에 사용하지 않았다.

## 확인한 동작

| 상황 | 기대 결과와 확인 방법 |
|---|---|
| 첫 ASR 호출 전에 종료 | 녹음 전 표식 또는 이전 앱의 녹음 상태로 WAV를 별도 복구하고 재생 길이를 확인한다. 원본 바이트와 메모는 그대로다. |
| WAV 헤더 미완성·마지막 샘플 불완전 | 디스크에 남은 완전한 PCM만 복구한다. 기존 복구본의 내용이 다르면 덮어쓰지 않는다. |
| 완성 WAV 뒤의 LIST 메타데이터 | 메타데이터를 음성 샘플로 처리하지 않는다. |
| 녹음 앱의 소유 파이프 EOF | Swift 종료 정리 없이 감독 프로세스와 가짜 상주 엔진이 종료된다. |
| 교정 도중 잠자기 | 원문이 보관함에 공개되지 않는다. 깨우면 기존 ASR 체크포인트를 재사용한다. |
| 활성 교정 뒤에 요약만 대기 | 순서를 유지하고 두 번째 작업의 사용자 편집·메모를 보존한다. 요약 작업은 ASR을 호출하지 않는다. |
| 깨우기 직후 다시 잠자기 | 이전 세대의 깨우기 작업이 실행을 재개하지 않는다. |
| 잠자기 중 사용자가 작업 취소 | 깨우기·재실행에서도 자동 재개하지 않는다. |
| 손상된 음성 복구 실패 | 원본과 항목은 남고 음성 다시 확인을 제공한다. 잘못된 파일로 교정을 시작하지 않는다. |
| 전체 교정 입력 | 일반·긴 가상 강의 모두 한 요청에 전체 문장과 수정 대상 ID를 담는다. |
| 용량 초과 | 문장 경계에서 이분할을 반복한다. 순서·ID의 누락이나 중복이 없고, 완료한 부분만 캐시한다. |
| 분할 후 뒤쪽 요청 실패 | 최종 교정본은 공개하지 않는다. 재시도는 완료 부분과 분할 결정을 재사용한다. |
| 인증·네트워크·할당량 실패 | 용량 초과로 잘못 해석하여 요청을 늘리지 않는다. 모델 답변 속 오류 문자열도 무시한다. |
| AI 연결 없음·교정 검증 실패 | 원문은 내부 체크포인트에만 남는다. 연결 후 재시도하면 ASR을 반복하지 않는다. |
| 교정 완료 뒤 요약 실패 | 교정된 전사문과 재생 위치를 사용할 수 있다. |
| 시간 기반 교정 진행률 | 경과 시간에 따라 단조롭게 증가하고 90%를 넘지 않는다. 실제 완료만 100%를 만든다. |

## 실행 범위

앱 `swift test` 97개, Codex 코어 13개를 통과했다. 전사 코어 16개 중 15개를 통과했으며 설치 모델 선택 테스트 1개는 실행하지 않았다. 각 저장소의 release 빌드도 확인했다. UI는 격리된 샘플 라이브러리로 중단·잠자기·교정·기존 공개본 재처리 화면을 렌더링하고, 창 표시·활성화 없이 생성되는지 감시했다. 개발 기록과 이미지는 비공개 `.local/interruption-recovery/`에 보관한다.

실제 노트북 덮기, 배터리 방전, 전원 차단, USB 마이크 교체 조합을 물리적으로 실행한 검증은 아니다. 실제 AI의 교정 품질과 대기 시간도 가짜 공급자 테스트로 증명하지 않는다. 시간 기반 진행률의 기본값은 실측 속도 보장이 아니다.
