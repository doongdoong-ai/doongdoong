# 공급자 분리와 진행 화면 검증 · 2026-10-21

이번 변경은 인식 모델의 정확도 비교가 아니라 **Codex 연결의 모듈화와 처리 진행 상태의 정확성**을 검증한다. 기존 Whisper large-v3-turbo 음성 인식과 교정·강조 판정 규칙을 유지했다.

## 검증한 구성

| 구성 | 버전·범위 |
|---|---|
| 전사 코어 | `doongdoong-ai/transcription-core` 0.1.1, 저장한 음성 구간의 진행 콜백 |
| 텍스트 공급자 | `doongdoong-ai/codex-core` 0.1.0, 공급자 공통 계약과 Codex CLI 연결 |

| Codex 호환 확인 | 설치된 CLI 0.160.0의 옵션과 공식 app-server 문서 |

## 자동 검사

- 앱 88개 테스트 통과. Codex와 무관한 테스트 공급자로 원문·문장 ID·타임스탬프 보존 및 교정·요약을 실행했다.
- 공급자 코어 11개 테스트 통과. 모델 목록 페이지 처리, 명시적 모델 선택, 추론 강도 검증, API 키 로그인 거부, 크기 제한, 취소 및 임시 파일 정리를 확인했다.
- 전사 코어는 12개 중 11개 통과, 실제 엔진을 요구하는 선택적 검사 1개 생략. 새 검사는 중간 실패 전후의 완료량, 재개와 마지막 구간을 확인한다.
- 실패한 교정 응답을 재시도해도 완료 수는 증가하지 않는다. 검증을 통과하고 저장한 문장 묶음만 완료로 센다.
- 공급자·모델·추론 강도가 다르면 교정 캐시를 공유하지 않는다. 실행 중 설정을 변경해도 기존 작업의 설정 스냅샷은 바뀌지 않는다.
- 모델 목록은 앱 실행마다 다시 확인한다. 취소된 과거 조회가 새 조회 결과를 덮어쓰지 않는다.

공개 저장소에서 받은 두 패키지의 정확한 버전을 `Package.resolved`에 고정하고 앱 테스트와 release 빌드를 수행했다. 기본 테스트는 가짜 CLI·음성 인식기·텍스트 공급자를 쓰므로 녹음이나 클라우드 추론을 실행하지 않는다.

## 화면 검사

공급자 설정, 상세 옵션, 전사 진행 화면, 기존 전사문 위 교정 진행 패널을 메모리에 렌더링해 확인했다. 상세 옵션은 펼친 내용을 확인하기 위해 높이를 확장한 캔버스를 사용한다. 실제 설정 창은 스크롤된다.

렌더링 검사는 화면 전환을 일으키지 않아야 한다. 검사 프로세스의 활성화 정책, 보이는 창 수 0, 앱 활성화 및 최전면 전환 없음도 함께 검사한다. 결과와 스크린샷은 비공개 `.local`에 보관한다.

## 이번 결과로 말할 수 없는 것

이번 변경에서 실제 강의 전체를 클라우드로 다시 보내지는 않았다. 신규 장시간 정확도, 실제 계정의 잔여 한도, 모든 CLI 버전과의 호환성을 보장하는 결과가 아니다. 과거 ASR 비교는 [평가 프로토콜](evaluation/protocol.ko.md)의 조건과 별도로 해석해야 한다.
